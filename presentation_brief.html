동아리 시설 예약 에이전트

카페 에이전트 대비 무엇이 같고 무엇이 새로운가 — 발표 노트

한 줄 소개

동아리 간부가 세미나실·대강당·동아리방·스튜디오를 예약할 때, 시간이 겹치지 않는 빈 시간대를 직접 찾아 예약까지 해주는 비서입니다.

구조: 그대로 복사한 것 vs 새로 만든 것

에이전트 루프, LLM 연결, 설정은 커피도 시설도 모릅니다 — 도메인 지식은 전부 도구와 데이터에 들어 있습니다.

그대로 복사 (수정 없음)

config.py · llm_client.py · agent.py · main.py · data_store.py · calculator.py

새로 작성

facility_tools.py · schedule_tools.py · data/*.json · tool_spec.md · system_prompt.md · test_tools.py · app.py(웹 UI, 카페 패턴 참고해 재작성)

도구 비교

4개 전부 새로 설계한 도구이고, calculate만 그대로 재사용했습니다.

분류카페 에이전트동아리 시설 예약 에이전트
read get_menu · check_stock get_facility_info · check_schedule
compute calculate calculate(재사용) · find_available_slot
write record_sale reserve_facility
집계 리포트 get_sales_report 없음 — 다음 스트레치 과제 후보

핵심 차별점: find_available_slot

카페에는 "같은 시간, 같은 자리"를 두 손님이 다툴 일이 없습니다. 우리 도구는 그 문제를 푸는 구간 스케줄링 계산입니다.

cursor = 운영 시작 시각
for 예약 in 그날의_예약들_시작시간순:
    if 예약.시작 - cursor >= 원하는_길이:
        return [cursor, cursor + 원하는_길이]   # 빈 틈 발견
    cursor = max(cursor, 예약.종료)
if 운영_종료 - cursor >= 원하는_길이:
    return [cursor, cursor + 원하는_길이]        # 마지막 틈
return 없음

예약과 예약 사이의 틈(gap)을 순서대로 검사한다는 점이 get_menu·check_stock처럼 "지금 값 하나 조회"와 다른 부분입니다. reserve_facility도 같은 충돌 검사를 쓰고, 실패하면 에러 메시지가 "find_available_slot을 호출하라"고 다음 행동을 알려줍니다 — 그냥 거부가 아니라 복구 경로 제시.

"이름만 바꾸기" 테스트로 검증

도구카페 단어로 바꾸면결과
check_schedule"커피의 일정?"의미 없음 → 통과
find_available_slot"커피가 빌 시간?"의미 없음 → 통과
reserve_facility"커피 예약?"구조는 record_sale과 비슷하지만, 운영시간·충돌 이중 검증 로직이 추가됨
get_facility_info"메뉴 정보?"get_menu와 구조 유사 (정보 조회) — 그래서 차별화 근거는 아님

검증하며 배운 것

단순히 "작동했다"가 아니라, 실제로 돌려보며 고친 과정입니다.

✓pytest 21개 전부 통과 (read/write/compute 전 도구, 정상·오류 케이스)
✓실제 LLM로 3개 시나리오(연쇄 호출 / 쓰기 전 확인 / 오류 회복) 라이브 테스트
!1차 모델(gpt-oss-20b)은 사용자가 "예약해줘"라고 확인해도 도구를 호출하지 않거나, 오류 상황에서 존재하지 않는 시설 이름을 지어냄
✓에이전트 코드가 아니라 모델(gpt-oss-120b)과 시스템 프롬프트 규칙을 고쳐 해결 → 슬라이드 18 원칙("틀리면 코드 말고 설명/프롬프트") 실제 적용
